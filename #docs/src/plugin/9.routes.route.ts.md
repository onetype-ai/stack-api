# routes/

The http surface, one file a resource. A handler reads `input` and calls a
service; the logic is not here. `input` is params, query and body, parsed and
merged. `output` is an allow-list: a field it does not name never leaves.
Every route says what it `requires`, or is marked `public`, and carries a
`limit`: a closed route without one is refused as `[unbounded]`.

```ts
const route = defineRoute<ItemsContext>();

export const itemsRoutes: readonly AnyRoute<ItemsContext>[] = [
    route({
        method: "GET",
        path: "/items/:id",
        describe: "Answers one item of the caller's tenant.",
        requires: ["items.read"],
        limit: { requests: 120, seconds: 60 },

        input: z.object({ id: z.uuid() }),
        output: Item.schema,
        handle: async (input, ctx) =>
        {
            return ctx.services.items.get(input.id);
        },
    }),

    route({
        method: "POST",
        path: "/items",
        describe: "Creates an item in the caller's tenant.",
        requires: ["items.write"],
        limit: { requests: 20, seconds: 60 },

        input: z.object({ title: z.string().max(200) }),
        output: Item.schema,
        handle: async (input, ctx) =>
        {
            const item = await ctx.services.items.create(input.title);

            return new Reply(201, item, { location: `/items/${item.id}` });
        },
    }),
];
```

A GET changes nothing: state changes go through POST, PATCH, PUT or DELETE.
