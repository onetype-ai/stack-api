# schemas/

Everything zod parses: what crosses the boundary, and the config read at
startup. `Item.ts` holds `Item`, as a `const` and a `type` of one name.
`schema` parses where it is named; a member does what zod cannot express.

```ts
import { Refusal } from "@onetype/stack-api-kit";
import { z } from "zod";

export const Item = {
    schema: z.object({
        id: z.uuid(),
        title: z.string(),
        createdAt: z.number().int(),
    }),

    title: (raw: string): string =>
    {
        const title = raw.trim();

        if (title === "")
        {
            throw new Refusal(400, "BAD_TITLE", "A title holds something besides spaces.", {
                title: "Write at least one character.",
            });
        }

        return title;
    },
};

export type Item = z.infer<typeof Item.schema>;
```

Config is `ItemsConfig.ts`, read from `ITEMS__<FIELD>`. A secret declares no
`.default()`, or the fallback is published. A fake provider (mail, payments)
is refused when `Env.isProduction()` unless `Env.allowsFake()`; the real one
is a secret in the environment, never a code change.

A schema that reads stored rows (a JSON column) is `Stored.define("items.details",
schema)`. It may only widen: `pnpm stored:accept` records it, and a test
refuses a change an older row would fail.
