# schemas/

Everything zod parses: what crosses the boundary, and the config read at
startup. `<Type>.ts` holds `<Type>`, as a `const` and a `type` of one name.
A secret declares no `.default()`, or the fallback value is published.

Config naming a provider the owner has no account for yet (mail, payments)
takes a fake one only behind `allowFake`, read as `<PLUGIN>__ALLOW_FAKE`, and
refuses it when `NODE_ENV` is `production`: switching to the real provider is a
secret in the environment, never a code change.

`schema` parses where it is named; `<member>` a service calls, for what
zod cannot express.

```ts
import { Refusal } from "@onetype/stack-api-kit";
import { z } from "zod";

export const <Type> = {
    schema: z.object({
        id: z.uuid(),
        <field>: z.string(),
    }),

    <member>: (raw: string): string =>
    {
        if (<describe>)
        {
            throw new Refusal(400, "BAD_<FIELD>", "<describe>", {
                <field>: "<describe>",
            });
        }

        return <raw, made regular>;
    },
};

export type <Type> = z.infer<typeof <Type>.schema>;
```

A member taking `<Type>` rather than a field of it makes the object reference
its own type. Lift the schema to a `const` above and derive the type from
that, so the object is free to use it.
