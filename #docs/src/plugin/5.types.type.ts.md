# types/

Shapes describing code alone: nothing here crosses the boundary, and nothing
parses. `<Type>.ts` holds `<Type>`, except `Context.ts`, which holds
`<Plugin>Context`.

Three every plugin has. `plugin.ts` names the first two in `over`; the third
is the `ctx` a service, a route and a listener are each written against.

`<Plugin>Db.ts`

```ts
import type { BetterSQLite3Database } from "drizzle-orm/better-sqlite3";

import type { <plugin> } from "../tables/<plugin>";

export type <Plugin>Db = BetterSQLite3Database<{ <plugin>: typeof <plugin> }>;
```

`<Plugin>Services.ts`

```ts
import type { <Plugin> } from "../services/<plugin>";

export type <Plugin>Services = {
    <service>: <Plugin>;
};
```

`Context.ts`

```ts
import type { Context } from "@onetype/stack-api-kit";
import type { z } from "zod";

import type { <Plugin>Config } from "../schemas/<Plugin>Config";
import type { <Plugin>Db } from "./<Plugin>Db";
import type { <Plugin>Services } from "./<Plugin>Services";

export type <Plugin>Context = Context<z.infer<typeof <Plugin>Config.schema>, <Plugin>Services, <Plugin>Db>;
```

The rest is whatever the code needs and no caller receives.
