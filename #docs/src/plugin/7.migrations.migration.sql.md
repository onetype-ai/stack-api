# migrations/

Generated from `tables/`, never written by hand, one folder a dialect:

```
pnpm migrations items items
```

```
migrations/
├── sqlite/0000_items.sql
└── postgres/0000_items.sql
```

Both folders hold the same numbered steps; verify names a gap
`[migrations]`. Read what was generated before committing it, with its `meta/`: the next
step is generated against it. A step that
already ran is never edited: databases would diverge while reporting the same
version. Change the table and generate a new one.

`postgres/0000_items.sql`

```sql
CREATE TABLE "items_items" (
	"id" text PRIMARY KEY NOT NULL,
	"tenant_id" text NOT NULL,
	"title" text NOT NULL,
	"is_archived" boolean DEFAULT false NOT NULL,
	"created_at" bigint NOT NULL
);
--> statement-breakpoint
CREATE INDEX "items_items_by_created" ON "items_items" USING btree ("tenant_id","created_at");
```

The contract names the parent folder: `migrations: "./src/plugins/items/migrations"`.
